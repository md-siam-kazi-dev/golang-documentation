# Taste
- Communicates in terse, informal shorthand with typos and minimal punctuation (e.g., "Read Prd.md ,also read sidebar.json for sidebar . create all route for sidebar", "some table content are not work properly . also implement terminal style where code exist"); expects the assistant to fill in the details by reading project files, diagnosing root causes, and inferring intent. Confidence: 0.8
- Wants demo/placeholder content scaffolded first so they can drop in the real content later ("add demo context now . I will add md file letter"). Prefers a working skeleton with clearly-marked placeholder bodies over waiting for final copy. Confidence: 0.7
- Prefers site routes/navigation to be driven from a config file (sidebar.json) via a re-runnable generator, rather than hand-maintaining each route/file individually. Confidence: 0.5
- Authors documentation content as plain Markdown files in a separate content folder (e.g., `public/doc/`), not directly as MDX in the site's content tree; expects the assistant to migrate/convert those files into the rendering pipeline (frontmatter, slug matching, section splitting) when wiring them in. Explicitly points the assistant at `public/doc/` when delivering new authored content ("i already added necessary md file in /public /doc") and expects the existing fundamentals-style transfer to be extended to the new section rather than hand-writing files. Delivers these files incrementally, in batches per section across successive rounds (first Fundamentals, then a few Core Programming topics, later the remaining core topics via "here alreay added file for go core . implement this"); each round the assistant should detect the newly added files and extend that section's transfer mappings so all sidebar topics get real content overwriting their placeholders. Confidence: 0.9
- Grants the assistant latitude to restructure their source content for a better site architecture — splitting combined files into separate pages, renaming/slugifying to match the sidebar, renumbering sections — rather than requiring 1:1 fidelity to the authored files. Confidence: 0.5
- Treats `public/sidebar.json` as the source of truth for topic slugs/page naming: content files must match the sidebar's expected filename/slug exactly (found a stale `custom-errors.mdx` vs sidebar topic "Custom Error" singular), and any drift is a defect to fix rather than something to accommodate. Confidence: 0.6
- Any text surfaced in the UI from generated meta (e.g., `description` shown in the prev/next bottom-nav cards) must be clean plain text — auto-derived descriptions need inline markdown (`**bold**`, `` `code` ``, `[link](url)`) stripped at generation time, never passed through raw. Confidence: 0.6
