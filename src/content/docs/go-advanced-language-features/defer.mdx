## Introduction

`defer` tells Go:

> "Run this function later, when the surrounding function is about to return."

It is extremely useful for cleanup:

- closing files
- closing database rows
- unlocking mutexes
- closing HTTP response bodies
- releasing resources

## 1. Basic Example

```go
package main

import "fmt"

func main() {
    defer fmt.Println("Second")
    fmt.Println("First")
}
```

Output:

```text
First
Second
```

The deferred statement runs when `main()` is about to finish.

## 2. Multiple defer Statements

Deferred calls follow LIFO order:

```text
Last In, First Out
```

Example:

```go
func main() {
    defer fmt.Println("First")
    defer fmt.Println("Second")
    defer fmt.Println("Third")
}
```

Output:

```text
Third
Second
First
```

Think of it as a stack:

```text
defer First
defer Second
defer Third

Stack:
Third  ← runs first
Second
First   ← runs last
```

## 3. Defer Is Executed When the Function Returns

```go
func example() {
    fmt.Println("Start")

    defer fmt.Println("Cleanup")

    fmt.Println("End")
}
```

Output:

```text
Start
End
Cleanup
```

## 4. Defer With return

```go
func example() int {
    defer fmt.Println("Deferred")
    return 10
}
```

The deferred function executes before `example()` actually returns to its caller.

## 5. Arguments Are Evaluated Immediately

This is one of the most important rules.

```go
func main() {
    x := 10

    defer fmt.Println(x)

    x = 20
}
```

Output:

```text
10
```

Why?

The argument to the deferred call is evaluated when `defer` is encountered.

Conceptually:

```go
defer fmt.Println(10)
```

not:

```go
defer fmt.Println(20)
```

## 6. Defer With Closures

A closure behaves differently because it reads the variable when the deferred function executes.

```go
func main() {
    x := 10

    defer func() {
        fmt.Println(x)
    }()

    x = 20
}
```

Output:

```text
20
```

The function captures `x`.

## 7. Closing a File

A common real-world pattern:

```go
file, err := os.Open("data.txt")

if err != nil {
    return err
}

defer file.Close()
```

After `os.Open()` succeeds, we immediately schedule cleanup.

This is much safer than remembering to call `Close()` at every return point.

## 8. Database Example

With database rows:

```go
rows, err := db.Query("SELECT id, name FROM users")

if err != nil {
    return err
}

defer rows.Close()
```

Now `rows.Close()` will run when the surrounding function returns.

## 9. Mutex Example

```go
mu.Lock()
defer mu.Unlock()

// Work with shared data
```

This prevents forgetting to unlock the mutex on one of the return paths.

## 10. Defer During Panic

Deferred functions also execute when a panic happens.

```go
func example() {
    defer fmt.Println("Cleanup")

    panic("something went wrong")
}
```

Output includes:

```text
Cleanup
```

This is one reason `defer` is important for resource cleanup.

## 11. Defer and Named Return Values

Deferred functions can modify named return values.

```go
func example() (result int) {
    defer func() {
        result++
    }()

    return 10
}
```

The returned result becomes:

```text
11
```

The simplified flow is:

```text
result = 10
↓
defer runs
↓
result = 11
↓
return
```

## 12. Common Mistake: Deferring Inside a Large Loop

Consider:

```go
for _, filename := range files {
    f, err := os.Open(filename)
    if err != nil {
        return err
    }

    defer f.Close()
}
```

All the `Close()` calls are delayed until the surrounding function returns.

If the loop processes many files, many files may remain open.

A better approach is to put the work inside a helper function:

```go
func processFile(filename string) error {
    f, err := os.Open(filename)
    if err != nil {
        return err
    }
    defer f.Close()

    // Process file
    return nil
}
```

Now each call closes its file when `processFile` returns.

## 13. Teacher Rule

When you successfully acquire a resource, think:

```text
Acquire resource
      ↓
Immediately defer cleanup
      ↓
Use resource
      ↓
Function returns
      ↓
Cleanup happens
```

Example:

```go
file, err := os.Open("data.txt")
if err != nil {
    return err
}
defer file.Close()
```

## Summary

Remember:

- `defer` delays a function call.
- Deferred calls run when the surrounding function returns.
- Multiple defers use LIFO order.
- Arguments are evaluated when `defer` is executed.
- Closures can observe later variable changes.
- Deferred functions execute during panic unwinding.
- `defer` is excellent for cleanup.

### Mental Model

```text
defer cleanup()

        ↓

"Don't run now.
Run when this function is leaving."
```
